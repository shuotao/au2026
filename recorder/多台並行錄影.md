# 同一時段錄多堂課（多軌並行）

> 這是一份**實戰筆記**，不是程式功能。`au2026rec` 本身一次只管一條時間軸；
> 要同時錄兩堂以上的直播，就開多份、每份各自有自己的設定、自己的 OBS、自己的瀏覽器。
> 2026-09-16～09-18 的 AU2026 期間，以這個做法**同時跑到六軌**，本文記錄怎麼做與踩到什麼。

## 什麼時候需要

直播撞期。`plan` 會把撞期的直播標成 `×` 要你自己取捨 —— 因為一台 OBS 同一時間只能錄一件事。
真的兩堂都要，就得開第二份。

不需要的情況：撞期的是 On-demand（收藏）。那些活動後補錄就好，不要為了它們開多軌。

## 一軌 = 三件東西各一份

| 元件 | 每一軌要獨立的地方 |
|---|---|
| `au2026rec` 的工作資料夾 | 自己的 `config.toml`、自己的課表 CSV、自己的 `logs/` |
| OBS | 各自的實例（可攜模式），**obs-websocket 埠號各自不同** |
| 瀏覽器 | 各自的 `--user-data-dir` 與 `--remote-debugging-port` |

程式本體（exe）只要一份，多軌共用；靠「在哪個資料夾執行」決定讀哪份設定。

```
recorder\
  au2026rec\          ← exe 與 _internal，六軌共用
  A\  config.toml  my_schedule.csv  logs\   ← 第一軌
  B\  config.toml  my_schedule.csv  logs\   ← 第二軌
  ...
```

每一軌的 `config.toml` 只有這幾個值不一樣：

```toml
[obs]
port = 4455          # 第二軌 4456、第三軌 4457…

[browser]
cdp_url = "http://localhost:9231"   # 第二軌 9232、第三軌 9233…
attach_profile_dir = "attach-profile"   # 各自資料夾底下，天然就分開了
```

啟動就是在各自的資料夾裡跑 `au2026rec.exe run --live -y`（每一軌一個視窗）。

## OBS：可攜模式多開

同一份安裝的 OBS 不能開兩個。作法是把整個 OBS 資料夾複製幾份，各自用可攜模式啟動：

```
obs-au\A\   obs-au\B\   obs-au\C\ …
```

每一份在自己的 `obs-studio\` 設定裡開啟 WebSocket 伺服器、給不同埠號（4455、4456…），
錄影輸出路徑也各自分開，這樣檔案不會混在一起。

## ⚠ 場景不能用「螢幕擷取 + 桌面音訊」

單軌的引導設定建立的是**螢幕擷取 + 桌面音訊**。多軌照抄會有兩個問題：

1. 六軌錄到的畫面一模一樣（都是同一個螢幕）
2. **聲音全部混在一起** —— 桌面音訊錄的是系統混音後的結果，六堂課的講者會疊在同一條音軌上

多軌要改成**每一軌只抓自己的那個瀏覽器視窗**：

| 來源 | 用什麼 |
|---|---|
| 畫面 | **視窗擷取**（Windows 10/11 用 WGC），綁到該軌瀏覽器的視窗 |
| 聲音 | **應用程式音訊擷取**（`wasapi_process_output_capture`），綁到該軌的瀏覽器程序 |

這樣六軌各錄各的，互不干擾；視窗被其他視窗蓋住也照錄（WGC 抓的是視窗本身）。

> 額外好處：**系統主音量、靜音鍵不影響錄到的聲音**（實測：主音量 50%／靜音／2%，
> 錄出來的 mean volume 都在 −20 dB 上下）。你可以把喇叭關掉、戴耳機聽其中一堂，
> 其他五堂照樣錄得到完整聲音。
>
> 但**混音器裡把那個瀏覽器本身的音量調小會錄進去**（同一次實測：100% → −20.5 dB、
> 10% → −40.6 dB、靜音 → −91 dB）。所以要調的是「系統／裝置」那一層，不是應用程式那一層。

## 取景

視窗擷取抓到的是整個瀏覽器視窗，上面那條分頁列與網址列也會錄進去。兩個做法：

* OBS 的來源變換裡**裁掉頂端**（分頁列＋網址列的高度；高 DPI 螢幕記得乘上縮放倍率）
* 邊界類型用 `OBS_BOUNDS_SCALE_INNER`，讓畫面等比填滿輸出解析度

課程頁本身留白很多的話，另一個辦法是讓播放器填滿整個分頁（注入一段 CSS 把 `.video-js`
設成 `position: fixed; inset: 0`）。這是自己動手的部分，程式不做。

**重新綁定視窗之後（瀏覽器重開、螢幕插拔、重新建立場景），裁切與縮放要重設一次** ——
這是實際踩過的坑：忘了重設，整場錄下來是偏掉的畫面。

## 六軌的實際負載

一台筆電、六軌 1080p 同時錄（Intel Core i9-14900HX／64 GB RAM／RTX 4090 Laptop）：

| 指標 | 實測 |
|---|---|
| CPU | 約 30% |
| 可用記憶體 | 還剩 17 GB |
| GPU 使用率 | 約 50%，65°C |
| NVENC 編碼工作階段 | 6 |
| OBS 掉幀 | 0 |

檔案大小約 **23 MB/分鐘**（1080p），一場 60 分鐘約 1.4 GB；六軌三天大概要準備 100 GB 以上。

> **上限不在 CPU，在 NVENC 的同時編碼數。** GeForce 卡有這個限制（依卡與驅動版本而定，
> 近年的驅動放寬了數量），超過就會有軌開不起來。硬體編碼不夠用時，剩下的軌改用
> 軟體編碼（x264）也行，但 CPU 佔用會跳上去，要自己衡量。

## 踩過的坑

| 狀況 | 結果 | 對策 |
|---|---|---|
| **Windows Update 自動重開機** | 六軌全斷，當天那幾場全沒了 | 活動期間先把自動更新暫停（設定 → Windows Update → 暫停更新） |
| **瀏覽器重開後還原了舊分頁** | OBS 綁的視窗變成別的分頁，錄到錯的畫面 | 重開後確認每一軌的分頁，再重新綁定視窗、重設裁切 |
| **把瀏覽器「正常關閉」** | 登入狀態沒了，六個 profile 要重登六次 | 不要關；真的要關，先確認 profile 目錄還在 |
| **螢幕休眠** | 視窗擷取仍然有畫面（比螢幕擷取耐打），但別冒險 | `powercfg /change monitor-timeout-ac 0` |
| **某一軌的 OBS 自己關掉** | 那一軌之後的場次全部沒錄到 | 每天開錄前逐軌 `obs-test` 確認連得上 |

## 一件事先想清楚

多軌代表**同一時段你只可能真的在看其中一堂**，其他都是「先錄起來以後看」。
先確認自己事後真的會看，再決定要開幾軌 —— 錄六軌很容易，看完十八個小時的錄影不容易。
